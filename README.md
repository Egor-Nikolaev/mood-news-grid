# Настроение новостей (Mood News Grid)

Страница реальных новостей, где один и тот же набор фактов можно читать в разных
эмоциональных режимах: нейтрально, радостно, грустно, иронично, тревожно.
**Меняется только тон. Факты (имена, числа, даты, цитаты) остаются неизменными и
проверяются кодом после каждой переписки.**

Ключевая идея тестового — не «переписать красиво», а показать **контроль фактов**:
как не дать модели соврать. Здесь это отдельный слой верификации, который сверяет
переписанный текст с оригиналом и, если факт потерян, чинит результат или откатывается
на детерминированный безопасный режим.

**Живое демо:** https://mood-news-grid-live.vercel.app

## Как запустить

```bash
npm install
npm run ingest      # подтянуть реальные новости из RSS в базу
npm run dev         # http://localhost:3000
```

LLM **не обязателен**: без ключа приложение работает на rule-based режиме и запускается
из коробки. Чтобы включить переписывание нейросетью — скопируй `.env.example` в `.env`
и вставь ключ любого OpenAI-совместимого провайдера. По умолчанию — Groq (быстрый,
щедрый бесплатный тариф), ключ создаётся бесплатно на console.groq.com:

```bash
cp .env.example .env
# LLM_BASE_URL=https://api.groq.com/openai/v1
# LLM_API_KEY=gsk_...          (бесплатно на console.groq.com)
# LLM_MODEL=llama-3.3-70b-versatile
```

Провайдер меняется одними переменными окружения — в комплекте закомментированный
блок для OpenRouter как запасной вариант. Код провайдер-агностичен (`lib/rewrite.js`).

Новости можно обновлять и из UI — кнопка «Обновить».

  api/rewrite/route.js    POST — переписать новость под настроение (+ кэш)

  db.js                   SQLite: схема, upsert новостей, кэш переписок

  facts.js                извлечение фактов + верификация их сохранности

## Мгновенный старт (снапшот)

На бесплатном serverless (Vercel) файловая система эфемерная: при холодном старте база
пуста. Чтобы первый посетитель не ждал загрузку RSS, в репозитории лежит `data/seed.json` —
снапшот реальных новостей с уже запечёнными переписками всех 5 настроений и результатами
верификации. `ensureSeeded()` грузит его мгновенно и без сети; клик по карточке отдаёт
готовый вариант из кэша, не дёргая лимитированный LLM. Кнопка «Обновить» подтягивает
свежие новости из RSS уже вживую. Пересобрать снапшот: `node scripts/build-seed.mjs`.

## Где хранятся данные

SQLite-файл `data/mood-news.db` (локально) или `/tmp` (на serverless). Две таблицы:

- **`articles`** — источник, ссылка на оригинал, заголовок, исходный текст,
  дата публикации, дата загрузки и `facts_json` (кэш извлечённых фактов). Дедуп по
  уникальному `guid`.
- **`rewrites`** — кэш переписок: пара `article_id + mood` уникальна, хранятся текст,
  метод (`llm` / `llm+repair` / `rule-based` / `rule-based(fallback)`), флаг `verified`
  и список нарушений. Повторный запрос той же пары не ходит в LLM.

## Как переписывается тон

`lib/rewrite.js`, стратегия по убыванию приоритета:

1. **LLM** (любой OpenAI-совместимый провайдер; по умолчанию Groq, модель
   `llama-3.3-70b-versatile`). Системный промпт на русском жёстко требует: менять только
   тон, а имена, числа, деньги, проценты, даты и цитаты оставлять дословно, ничего не выдумывать.
2. Ответ прогоняется через **верификацию фактов**. Всё на месте — отдаём (`method: llm`).
3. Факт потерян — **одна попытка починки**: модели явно перечисляются пропавшие факты
   с требованием вернуть их дословно (`method: llm+repair`).
4. LLM недоступен (нет ключа, rate-limit, сеть) или после починки всё ещё врёт —
   **rule-based фолбэк**: исходный текст оборачивается рамкой настроения, факты не
   редактируются by design, верификация всегда проходит.

Кэш переписок **адресуется хэшом текста новости** (`textKey` в `lib/facts.js`), а не
autoincrement id. Поэтому показать чужую переписку невозможно, и результат не зависит от
того, с какого serverless-инстанса пришёл запрос. Грид отдаёт готовые переписки всех
настроений вместе со списком новостей — переключатель тона меняет карточки **мгновенно**,
без похода в LLM; клик по новости тоже открывает переписанный текст сразу.

Модель по умолчанию — `llama-3.3-70b-versatile` через Groq: живой рерайт свежей новости
занимает ~1–2 секунды, поэтому кнопка «Обновить» даёт настоящую генерацию на лету без
ожидания. Если провайдер всё же ответит лимитом или сеть отвалится, переписка честно уйдёт
в rule-based — это видно в бейдже (поле «метод»), приложение при этом не падает. Демо-новости
(снапшот) запечены заранее живым LLM, поэтому открываются мгновенно и без похода в сеть.

**Фильтр контента.** Переписывать «радостно» новость про войну, теракт или гибель людей
морально-этически неуместно, поэтому такие темы отсекаются ещё на ингесте (`isSensitive`
в `lib/ingest.js`: война, насилие, жертвы, катастрофы). Плюс детектор отказов модели:
если LLM отказывается или уходит в мета-ответ, это считается провалом и включается
безопасный фолбэк, а не показывается «Извините, я не могу…».

## Как проверяется сохранение фактов

`lib/facts.js` — это «фишка» решения. Все regex на Unicode-классах (`\p{Lu}`, `\p{Ll}`,
`\p{L}` с флагом `u`), поэтому работает и русский, и латиница.

**Извлечение фактов** из оригинала:
- **числа**: деньги (`5 млрд руб`, `$5`, `₽100`), проценты, любые числа, годы;
- **даты**: русские и английские месяцы, дни недели, годы;
- **имена собственные**: мультислова с заглавной (`Дональд Трамп`), одиночные заглавные
  в середине предложения, аббревиатуры капсом (`НАТО`, `США`);
- **цитаты**: текст в «ёлочках», „лапках" и прямых кавычках.

**Верификация** (`verifyFacts`): каждый факт оригинала ищется в переписанном тексте
(нормализация регистра, пробелов, `ё→е`). Если хоть один не найден — это `violation`,
текст помечается как искажённый, срабатывает починка или фолбэк. В UI это бейдж
«Факты сохранены» / «Обнаружено искажение фактов» со списком потерянного.

**Точность имён.** Мультислова (`Дональд Трамп`) и аббревиатуры (`НАТО`) берём всегда;
одиночную заглавную в середине предложения — тоже (там заглавная = имя собственное);
заглавную в начале предложения берём через стоп-лист частых обычных слов, чтобы поймать
имя-субъект («Зеленский заявил…»), но не тащить «Спрос вырос…» или «Власти сообщили…».
Это эвристика: редкое обычное слово вне стоп-листа может попасть в имена. Поэтому поверх
неё добавлен **LLM-NER** (см. ниже) — он уточняет имена там, где regex не дотягивает.

## Сверх минимума: три усиления контроля фактов

Обязательные пункты ТЗ закрыты (таблица выше). Дополнительно усилена **главная ось задачи —
доказуемость сохранения фактов**:

**1. Подсветка фактов в сравнении.** В модалке каждый защищённый факт (имя, число, дата,
цитата) подсвечен и в оригинале, и в переписке, цвет кодирует тип. Видно глазами: тон
полностью другой, а те же сущности стоят на местах слева и справа. Это визуальное
доказательство того, что верификация не на словах. Реализовано на клиенте (`highlightFacts`
в `app/page.js`): факты матчатся по нормализованным подстрокам (`ё→е`, регистр), позиции
сохраняются посимвольно, перекрытия мержатся.

**2. Эвал-прогон и юнит-кейсы** (`npm run eval`, `scripts/eval-facts.mjs`). Слой фактов
покрыт кейсами в обе стороны: факт сохранён → `ok`; факт искажён → пойман (по типам
number/name/date/quote + нормализация кириллицы). Плюс независимый прогон по всему снапшоту:
**60 пар (12 новостей × 5 настроений), 0 «тихих» искажений** — то есть нет ни одной переписки,
где стоит `verified=true`, но факт реально потерян. Запуск ненулевым кодом валит CI, если
контроль дал течь.

**3. LLM-NER поверх эвристики** (`extractFactsSmart`, `extractNamesLLM` в `lib/facts.js`).
При живой генерации имена извлекаются гибридно: быстрый regex (база, всегда) + уточнение
моделью. Ключевая страховка от галлюцинаций: **в набор фактов попадают только сущности,
реально присутствующие в оригинале дословно** — если модель придумала лишнее, оно
отфильтровывается и не может сломать верификацию. На снапшоте NER добавляет ~15 корректных
имён сверх regex (замер в эвале, 0 мусорных). Отключается флагом `LLM_NER=0`.

## Что использовано из AI

- **Переписывание тона** — LLM через любой OpenAI-совместимый провайдер (по умолчанию
  Groq, `llama-3.3-70b-versatile`, настраивается в `.env`). Без ключа — детерминированный
  rule-based режим.
- **Извлечение сущностей (NER)** — LLM уточняет имена поверх regex-базы, но с жёстким
  фильтром: в факты попадает только то, что дословно есть в оригинале (анти-галлюцинация).
- **Контроль над фактами** держится НЕ на доверии к модели, а на детерминированном слое
  верификации в коде (`lib/facts.js`), который проверяет вывод модели и при необходимости
  откатывает его. AI используется для генерации и извлечения, но последнее слово — за кодом.

## Журнал разработки (как думали)

Хронология решений и развилок — не «что получилось», а **почему выбрано именно так**.
Совпадает с историей коммитов (`git log`).

**1. С чего начали: в чём вообще суть задачи.**
Первая развилка — что здесь проверяют. «Переписать новость в 5 тонах» умеет любая модель
в одном промпте. Значит фишка не в этом, а в обратной стороне: как **не дать модели соврать**,
меняя тон. Отсюда весь фокус сместился с «красиво переписать» на «доказуемо сохранить факты».
Это определило архитектуру: отдельный слой верификации, а не доверие к модели.
_(коммит: старт проекта)_

**2. Реальные новости, а не заглушки.**
ТЗ требует настоящий источник. Взяли 3 живых RSS (РБК, Meduza, Интерфакс), парсинг,
чистку HTML, дедуп по `guid`. Решили тянуть только summary, а не полный текст: короткий
абзац честнее показывает контроль фактов, чем простыня, и дешевле по токенам.

**3. Как гарантировать факты: не промптом, а кодом.**
Очевидный путь — попросить модель «сохрани имена и числа». Ненадёжно by design: модель
иногда всё равно теряет или выдумывает. Поэтому сделали детерминированный слой `lib/facts.js`:
regex на Unicode-классах вытаскивают из оригинала имена, числа, даты, деньги, проценты,
цитаты; после переписки `verifyFacts` сверяет, что каждый факт на месте. Модели не верим —
проверяем её выход кодом.

**4. Что делать, когда модель всё же соврала: деградация вместо падения.**
Придумали цепочку по убыванию: `llm` → если факт потерян, точечная **починка** (`llm+repair`,
модели прямо перечисляем пропавшее) → если и после этого врёт или недоступна, **rule-based
фолбэк**, который факты не трогает by design. Принцип: приложение никогда не падает и никогда
не показывает искажённый факт. В UI честно виден метод — это не прячется. _(живой пример
в модалке: бейдж «нейросеть исказила факт — система поймала и восстановила его», метод
`llm+repair`)_

**5. Кириллица сломала первую версию верификации.**
Изначальные regex были заточены под латиницу и на русских именах спотыкались. Переписали
все паттерны на Unicode-классы (`\p{Lu}`, `\p{Ll}`, `\p{L}` с флагом `u`) и добавили
нормализацию `ё→е`, регистра и пробелов при сверке. Заодно редизайн под русскую подачу.

**6. Serverless вскрыл два бага, которых не было локально.**
При деплое на Vercel: (а) файловая система эфемерная — первый посетитель видел пустую базу;
(б) кэш переписок адресовался autoincrement-id, и на разных инстансах это могло отдать
**чужую переписку** к чужой новости. Оба чинятся сменой модели данных: кэш адресуем
**хэшом текста новости** (`textKey`), а не id — тогда результат не зависит от инстанса и
чужое показать невозможно. Пустой экран закрыли снапшотом (см. п.7).

**7. Мгновенный первый экран: офлайн-снапшот.**
Чтобы не заставлять первого посетителя ждать загрузку RSS и генерацию, запекли `data/seed.json` —
реальные новости с уже готовыми переписками всех 5 настроений и результатами верификации.
`ensureSeeded()` грузит его без сети; переключение тона на гриде — мгновенное, из кэша.

**8. Этика: нельзя «радостно» про трагедию.**
Переписать войну или гибель людей в радостном тоне — недопустимо. Добавили фильтр
`isSensitive` на ингесте (война, насилие, жертвы, катастрофы отсекаются) плюс детектор
отказов модели: если LLM уходит в «Извините, я не могу…», это провал → безопасный фолбэк,
а не мета-ответ в лицо пользователю.

**9. Нейтральный режим оказался ловушкой.**
Сначала «нейтрально» просто отдавало оригинал как есть — тон и так нейтральный. Но это
нарушает пункт ТЗ «нельзя заранее вручную писать новости в настроении»: нейтралка обязана
быть **тоже сгенерирована нейросетью**, а не быть копией. Прогнали живой рерайт по всем 12
и добили до 12/12, где нейтральная версия — отдельный LLM-текст, не дубликат summary.

**10. Живая генерация упиралась в лимиты — сменили провайдера.**
На бесплатном тарифе первого провайдера живая генерация свежих новостей часто ловила 429 и
падала в rule-based. Вынесли LLM-вызов в env (`LLM_*`, провайдер-агностично) и переключили
на Groq: тот же OpenAI-совместимый интерфейс, но рерайт за ~1–2 секунды. Теперь «Обновить»
даёт настоящую генерацию на лету, а не фолбэк. OpenRouter остался запасным вариантом одной
строкой в `.env`.

**11. Добили доказуемость: подсветка, эвал, LLM-NER.**
Когда обязательное было готово, усилили именно суть задачи (контроль фактов), а не набор
фич: подсветка фактов в сравнении (видно глазами, что сущности на местах), эвал-прогон с
юнит-кейсами и проверкой 60 пар на «тихие» искажения, и LLM-NER поверх эвристики с фильтром
анти-галлюцинации. Подробнее — в разделе «Сверх минимума». Извлечение имён из эвристики
доросло до гибрида regex + модель.

**Что осознанно оставлено на потом.** NER — через LLM с фильтром по оригиналу, а не
специализированная модель (spaCy / Natasha в отдельном сервисе): для MVP гибрид regex+LLM
даёт нужный recall без второго рантайма. Полноценная NER-модель — возможный следующий шаг,
если поток новостей вырастет и захочется убрать LLM-вызов из пути извлечения.
