# Mood News Grid

Страница реальных новостей, где один и тот же набор фактов можно читать в разных
эмоциональных режимах: нейтрально, радостно, грустно, иронично, тревожно.
**Меняется только тон. Факты (имена, числа, даты, цитаты) остаются неизменными и
проверяются кодом после каждой переписки.**

Ключевая идея тестового — не «переписать красиво», а показать **контроль фактов**:
как не дать модели соврать. Здесь это отдельный слой верификации, который сверяет
переписанный текст с оригиналом и, если факт потерян, чинит результат или откатывается
на детерминированный безопасный режим.

## Как запустить

```bash
npm install
npm run ingest      # подтянуть реальные новости из RSS в базу (24 шт. из 3 источников)
npm run dev         # http://localhost:3000
```

LLM **не обязателен**: без ключа приложение работает на rule-based режиме и запускается
из коробки. Чтобы включить переписывание нейросетью — скопируй `.env.example` в `.env`
и вставь бесплатный ключ OpenRouter (модели с суффиксом `:free` стоят $0):

```bash
cp .env.example .env
# OPENROUTER_API_KEY=sk-or-...   (создаётся бесплатно на openrouter.ai)
```

Новости можно обновлять и из UI — кнопка «↻ Обновить новости».

## Архитектура

```
app/
  page.js                 UI: грид, переключатель настроения, модалка сравнения
  api/news/route.js       GET  — список новостей из базы
  api/ingest/route.js     POST — подтянуть свежие новости из RSS
  api/rewrite/route.js    POST — переписать новость под настроение (+ кэш в базе)
lib/
  db.js                   SQLite: схема, upsert новостей, кэш переписок
  feeds.js                список RSS-источников
  ingest.js               парсинг RSS, чистка HTML, извлечение фактов, запись в базу
  facts.js                извлечение фактов + верификация их сохранности
  moods.js                определения 5 настроений (промпт для LLM + rule-based рамка)
  rewrite.js              переписывание тона + верификация + починка + фолбэк
scripts/ingest.mjs        CLI-сидинг базы
data/mood-news.db         SQLite-файл (в .gitignore, создаётся при первом запуске)
```

## Где хранятся данные

SQLite-файл `data/mood-news.db`. Две таблицы:

- **`articles`** — источник, ссылка на оригинал, заголовок, исходный текст,
  дата публикации, дата загрузки и `facts_json` (кэш извлечённых фактов).
- **`rewrites`** — кэш переписок: `article_id + mood` уникальны, хранятся текст,
  метод (`llm` / `llm+repair` / `rule-based` / `rule-based(fallback)`), флаг
  `verified` и список нарушений. Повторный запрос той же пары не ходит в LLM.

## Как переписывается тон

`lib/rewrite.js`, стратегия по убыванию приоритета:

1. **LLM** (OpenRouter free-модель). Системный промпт жёстко требует: менять только
   тон и формулировки, а имена, числа, деньги, проценты, даты и цитаты оставлять
   дословно, ничего не выдумывать.
2. Ответ прогоняется через **верификацию фактов**. Если всё на месте — отдаём (`method: llm`).
3. Если факт потерян — **одна попытка починки**: модели явно перечисляются пропавшие
   факты с требованием вернуть их дословно (`method: llm+repair`).
4. Если LLM недоступен (нет ключа, лимит, сеть) или после починки всё ещё врёт —
   **rule-based фолбэк**: исходный текст оборачивается рамкой настроения, факты не
   редактируются by design, поэтому верификация всегда проходит.

## Как проверяется сохранение фактов

`lib/facts.js` — это и есть «фишка» решения.

**Извлечение фактов** из оригинала (title + summary):
- **числа**: деньги (`$5`, `€9m`), проценты, любые числовые значения, годы;
- **даты**: месяцы, дни недели, годы;
- **имена собственные**: последовательности слов с заглавной буквы, страны/организации,
  аббревиатуры капсом;
- **цитаты**: текст в кавычках.

**Верификация** (`verifyFacts`): каждый факт оригинала ищется в переписанном тексте
(нормализация регистра и пробелов). Если хоть один не найден — это `violation`, текст
помечается как искажённый, срабатывает починка или фолбэк. В UI это видно бейджем
«✓ Факты сохранены» / «✗ Обнаружено искажение фактов» со списком того, что потерялось.

Такой подход **строгий намеренно**: лучше ложно придраться к пропавшему слову, чем
пропустить искажение факта. Это осознанный размен в сторону безопасности.

### Известное ограничение

Извлечение имён — эвристика, не полноценный NER. Иногда в «имена» попадает обычное
слово с заглавной буквы в начале предложения (например `Unprecedented`). На rule-based
режим это не влияет (факты не трогаются), а на LLM-режиме лишь делает проверку строже.
Полноценный NER (spaCy / модель) убрал бы этот шум — это следующий шаг, а не блокер.

## Что использовано из AI

- **Переписывание тона** — LLM через OpenRouter (по умолчанию
  `meta-llama/llama-3.3-70b-instruct:free`, настраивается в `.env`). Опционально:
  без ключа работает детерминированный rule-based режим.
- **Контроль над фактами** держится НЕ на доверии к модели, а на детерминированном
  слое верификации в коде (`lib/facts.js`), который проверяет вывод модели и при
  необходимости откатывает его.
