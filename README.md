# Настроение новостей (Mood News Grid)

Страница реальных новостей, где один и тот же набор фактов можно читать в разных
эмоциональных режимах: нейтрально, радостно, грустно, иронично, тревожно.
**Меняется только тон. Факты (имена, числа, даты, цитаты) остаются неизменными и
проверяются кодом после каждой переписки.**

Ключевая идея тестового — не «переписать красиво», а показать **контроль фактов**:
как не дать модели соврать. Здесь это отдельный слой верификации, который сверяет
переписанный текст с оригиналом и, если факт потерян, чинит результат или откатывается
на детерминированный безопасный режим.

**Живое демо:** https://mood-news-grid-live.vercel.app

## Как запустить

```bash
npm install
npm run ingest      # подтянуть реальные новости из RSS в базу
npm run dev         # http://localhost:3000
```

LLM **не обязателен**: без ключа приложение работает на rule-based режиме и запускается
из коробки. Чтобы включить переписывание нейросетью — скопируй `.env.example` в `.env`
и вставь бесплатный ключ OpenRouter (модели с суффиксом `:free` стоят $0):

```bash
cp .env.example .env
# OPENROUTER_API_KEY=sk-or-...   (создаётся бесплатно на openrouter.ai)
```

Новости можно обновлять и из UI — кнопка «Обновить».

## Архитектура

```
app/
  layout.js               шрифты (Inter + Lora через next/font), метаданные
  globals.css             дизайн-система: токены, светлая/тёмная тема
  page.js                 UI: грид, переключатель настроения, модалка сравнения
  api/news/route.js       GET  — список новостей (+ авто-сидинг при пустой базе)
  api/ingest/route.js     POST — подтянуть свежие новости из RSS
  api/rewrite/route.js    POST — переписать новость под настроение (+ кэш)
lib/
  db.js                   SQLite: схема, upsert новостей, кэш переписок
  feeds.js                список RSS-источников
  ingest.js               парсинг RSS, чистка HTML, извлечение фактов, ensureSeeded
  facts.js                извлечение фактов + верификация их сохранности
  moods.js                определения 5 настроений (промпт для LLM + rule-based рамка)
  rewrite.js              переписывание тона + верификация + починка + фолбэк
scripts/ingest.mjs        CLI-сидинг базы из RSS
scripts/build-seed.mjs    генерация офлайн-снапшота (новости + запечённые переписки)
data/seed.json            снапшот реальных новостей + переписки всех настроений (коммитится)
data/mood-news.db         SQLite-файл (в .gitignore, создаётся при первом запуске)
```

## Мгновенный старт (снапшот)

На бесплатном serverless (Vercel) файловая система эфемерная: при холодном старте база
пуста. Чтобы первый посетитель не ждал загрузку RSS, в репозитории лежит `data/seed.json` —
снапшот реальных новостей с уже запечёнными переписками всех 5 настроений и результатами
верификации. `ensureSeeded()` грузит его мгновенно и без сети; клик по карточке отдаёт
готовый вариант из кэша, не дёргая лимитированный LLM. Кнопка «Обновить» подтягивает
свежие новости из RSS уже вживую. Пересобрать снапшот: `node scripts/build-seed.mjs`.

## Где хранятся данные

SQLite-файл `data/mood-news.db` (локально) или `/tmp` (на serverless). Две таблицы:

- **`articles`** — источник, ссылка на оригинал, заголовок, исходный текст,
  дата публикации, дата загрузки и `facts_json` (кэш извлечённых фактов). Дедуп по
  уникальному `guid`.
- **`rewrites`** — кэш переписок: пара `article_id + mood` уникальна, хранятся текст,
  метод (`llm` / `llm+repair` / `rule-based` / `rule-based(fallback)`), флаг `verified`
  и список нарушений. Повторный запрос той же пары не ходит в LLM.

## Как переписывается тон

`lib/rewrite.js`, стратегия по убыванию приоритета:

1. **LLM** (OpenRouter, бесплатная модель `google/gemma-4-26b-a4b-it:free`). Системный
   промпт на русском жёстко требует: менять только тон, а имена, числа, деньги, проценты,
   даты и цитаты оставлять дословно, ничего не выдумывать.
2. Ответ прогоняется через **верификацию фактов**. Всё на месте — отдаём (`method: llm`).
3. Факт потерян — **одна попытка починки**: модели явно перечисляются пропавшие факты
   с требованием вернуть их дословно (`method: llm+repair`).
4. LLM недоступен (нет ключа, rate-limit, сеть) или после починки всё ещё врёт —
   **rule-based фолбэк**: исходный текст оборачивается рамкой настроения, факты не
   редактируются by design, верификация всегда проходит.

Бесплатный тариф OpenRouter лимитирован: при частых запросах часть переписок честно
уходит в rule-based — это видно в бейдже (поле «метод»), приложение при этом не падает.

## Как проверяется сохранение фактов

`lib/facts.js` — это «фишка» решения. Все regex на Unicode-классах (`\p{Lu}`, `\p{Ll}`,
`\p{L}` с флагом `u`), поэтому работает и русский, и латиница.

**Извлечение фактов** из оригинала:
- **числа**: деньги (`5 млрд руб`, `$5`, `₽100`), проценты, любые числа, годы;
- **даты**: русские и английские месяцы, дни недели, годы;
- **имена собственные**: мультислова с заглавной (`Дональд Трамп`), одиночные заглавные
  в середине предложения, аббревиатуры капсом (`НАТО`, `США`);
- **цитаты**: текст в «ёлочках», „лапках" и прямых кавычках.

**Верификация** (`verifyFacts`): каждый факт оригинала ищется в переписанном тексте
(нормализация регистра, пробелов, `ё→е`). Если хоть один не найден — это `violation`,
текст помечается как искажённый, срабатывает починка или фолбэк. В UI это бейдж
«Факты сохранены» / «Обнаружено искажение фактов» со списком потерянного.

**Точность имён.** Мультислова (`Дональд Трамп`) и аббревиатуры (`НАТО`) берём всегда;
одиночную заглавную в середине предложения — тоже (там заглавная = имя собственное);
заглавную в начале предложения берём через стоп-лист частых обычных слов, чтобы поймать
имя-субъект («Зеленский заявил…»), но не тащить «Спрос вырос…» или «Власти сообщили…».
Это эвристика, а не полноценный NER: редкое обычное слово вне стоп-листа может попасть
в имена. Модельный NER (spaCy / Natasha) убрал бы остаток — это следующий шаг.

## Что использовано из AI

- **Переписывание тона** — LLM через OpenRouter (по умолчанию бесплатная
  `google/gemma-4-26b-a4b-it:free`, настраивается в `.env`). Без ключа — детерминированный
  rule-based режим.
- **Контроль над фактами** держится НЕ на доверии к модели, а на детерминированном слое
  верификации в коде (`lib/facts.js`), который проверяет вывод модели и при необходимости
  откатывает его.
